## T8080CPU from TCPU class in cpu_8080 unit

`T8080CPU` is the Intel 8080 processor implementation for the CoreLAB framework. It derives from `TCPU` and implements the Intel 8080 register set, reset operation, state persistence, instruction stepping, current-instruction reporting and register access.

The actual instruction implementation is included from `microcode.pas` during compilation. Therefore, the instruction set behaviour is distributed between this unit and that included microcode source.

### TLastInstruction

`TLastInstruction` stores information about the most recently fetched instruction.

|field|type|description|
|---|---|---|
|`Address`|`Word`|Address at which the instruction was fetched.|
|`Opcode`|`Byte`|Fetched opcode byte.|
|`NumOperand`|`Byte`|Number of operands stored in the log record.|
|`Operands`|`array[1..2] of Word`|Instruction operand values.|
|`Mnemonic`|`string[12]`|Instruction mnemonic.|

### T8080Registers

`T8080Registers` provides both 16-bit register-pair access and individual 8-bit register access through a variant record.

|16-bit register|8-bit representation|
|---|---|
|`BC`|`B`, `C`|
|`DE`|`D`, `E`|
|`HL`|`H`, `L`|
|`AF`|`A`, `F`|
|`PC`|`PCL`, `PCH`|
|`SP`|`SPL`, `SPH`|

The register set therefore contains the Intel 8080 accumulator, flags, general-purpose register pairs, program counter and stack pointer.

### Register names

The internal register-pointer table uses the following order:

|index|name|
|---:|---|
|0|`B`|
|1|`C`|
|2|`D`|
|3|`E`|
|4|`H`|
|5|`L`|
|6|`M`|
|7|`A`|

`M` has no direct register pointer because it represents the memory location addressed by `HL`.

|name|type|description|
|---|---|---|

|`LogRecord`|`TLastInstruction`|Raw information about the last fetched instruction.|
|`RegPointers`|`array[0..7] of PByte`|Pointers to the 8-bit register variables used by instruction implementation.|

### Protected methods

|name|flags|description|
|---|:---:|---|
|`procedure UpdateFlags(Value16: Word; OldValue, ValueToAdd: Byte);`| |Updates the Intel 8080 flag register according to the supplied arithmetic result.|

`UpdateFlags` handles the Sign, Zero, Auxiliary Carry, Parity and Carry flags. It also forces the Intel 8080 constant flag bits to their required values.

### Public methods

|name|flags|description|
|---|:---:|---|
|`constructor Create;`|Or|Creates an Intel 8080 CPU, configures its architecture parameters and register pointers, and performs a reset.|
|`procedure Reset;`|Or|Clears the register set, sets `PC` to `0`, sets `SP` to `$FFFF`, clears running and halt states, and emits `ceReset`.|

### CPU configuration

The constructor configures the inherited `TCPU` properties as follows:

|item|value|
|---|---|
|Module name|`8080`|
|Description|`Intel 8080 microprocessor`|
|Architecture|`arNeumann`|
|Bit width|8|
|Address width|16|
|Endianness|`enLittle`|
|Maximum memory address|`$FFFF`|
|Maximum code address|`$FFFF`|
|Maximum I/O port address|`$00FF`|
|Separate I/O bus|`True`|

The inherited CPU constructor is called first, after which the 8080-specific configuration is assigned and `Reset` is executed.

### Reset state

`Reset` clears the complete `T8080Registers` record and then explicitly assigns:

|register/state|value|
|---|---:|
|`PC`|`$0000`|
|`SP`|`$FFFF`|
|`Running`|`False`|
|`Halted`|`False`|

The method also emits the inherited `ceReset` event.

### Instruction execution

`Step` performs the following operations:

1. Calls `CheckInterrupts`; execution stops immediately when an interrupt is accepted.
2. Stops immediately if the CPU is halted.
3. Reads the opcode from the system bus at the current `PC`.
4. Stores the address and opcode in `LogRecord`.
5. Clears the operand count in the log record.
6. Increments `PC`.
7. Emits `ceInstructionBoundary`.
8. Includes and executes the instruction implementation from `microcode.pas`.
9. Increments the inherited instruction counter.

The source therefore requires a connected `FBus` for opcode fetching.

### Current-instruction format

`GetCurrentInstruction` returns a tab-separated textual representation containing:

1. the instruction address as four hexadecimal digits;
2. the opcode as two hexadecimal digits;
3. up to two encoded operand values;
4. the mnemonic;
5. the operand values again in the formatted operand portion.

The returned string is stored in the private `s` field before its character pointer is returned.

### Register access

`GetRegister` and `SetRegister` compare register names case-insensitively using `UpperCase`.

|register|width|readable|writable|
|---|---:|:---:|:---:|
|`A`|8 bit|Yes|Yes|
|`F`|8 bit|Yes|Yes|
|`BC`|16 bit|Yes|Yes|
|`DE`|16 bit|Yes|Yes|
|`HL`|16 bit|Yes|Yes|
|`PC`|16 bit|Yes|Yes|
|`SP`|16 bit|Yes|Yes|

`SetRegister` masks `A` and `F` to `$FF`, and `BC`, `DE`, `HL`, `PC` and `SP` to `$FFFF`.

Names not handled by the `case` statement have no effect in `SetRegister` and return `0` from `GetRegister`.

### State persistence

`LoadState` reads the following data in order:

|order|data|
|---:|---|
|1|`FEnabled`|
|2|`FRegs`|
|3|`FRunning`|
|4|`FHalted`|
|5|`FInterruptEnabled`|
|6|`FIRQPending`|
|7|`FNMIPending`|
|8|`FCycles`|
|9|`FInstructions`|

If a stream exception occurs, `LoadState` returns `False`; otherwise it returns `True`.

`SaveState` writes the same fields in the same order, but only when `InstanceID > -1`. When the instance ID is invalid, it returns `False`.

### Exported plugin interface

The unit is compiled as the `cpu_8080` dynamic library and exports four plugin entry points:

|exported name|function|description|
|---|---|---|
|`cpu_create`|`CreateCPU`|Creates and returns a new `T8080CPU` instance as `TCPU`.|
|`cpu_destroy`|`DestroyCPU`|Destroys the supplied CPU instance when it is assigned.|
|`cpu_loadstate`|`LoadState`|Loads state through the supplied `TCPU` reference. Returns `False` when the reference is `nil`.|
|`cpu_savestate`|`SaveState`|Saves state through the supplied `TCPU` reference. Returns `False` when the reference is `nil`.|

### Inherited interfaces

`T8080CPU` implements the abstract CPU interface supplied by `TCPU`, including the operations used through the CoreLAB control and service APIs:

- register access,
- reset,
- instruction stepping,
- current-instruction reporting,
- state loading and saving.

The actual bus access is performed through the inherited `FBus` reference.
