## T4040CPU from T4004CPU class in cpu_4040 unit

`T4040CPU` is the Intel 4040 processor implementation for the CoreLAB
framework. It derives from `T4004CPU` and extends the 4004 implementation
with a 13-bit program address space, 24 four-bit general-purpose registers,
a seven-level internal program-counter stack and interrupt handling.

The 4040-specific opcode implementation is included from
`cpu_4040_microcode.pas`. Opcodes not handled by the 4040-specific `case`
statement are passed to the inherited `T4004CPU.RunOpCode` implementation.

### Inheritance and inherited functionality

`T4040CPU` inherits the MCS-4 bus connection, state persistence, current
instruction reporting, register storage structures and the base 4004
execution support from `T4004CPU`.

|inherited member         |description                                                                                                 |
|-------------------------|------------------------------------------------------------------------------------------------------------|
|`FBus: IMCS4Bus`         |Connected external MCS-4 bus.                                                                               |
|`FRegs: T4004Registers`  |Register record containing the general registers, accumulator, program counter and command control register.|
|`FFlags: T4004Flags`     |Flag storage containing the carry flag.                                                                     |
|`FStack: T4004Stack`     |Internal program-counter stack; the 4040 configures it for seven entries.                                   |
|`ConnectBus`             |Connects to a bus supporting `IMCS4Bus`.                                                                    |
|`LoadState` / `SaveState`|Uses the inherited 4004 state format.                                                                       |
|`GetCurrentInstruction`  |Returns the inherited instruction log record.                                                               |
|`RunOpCode`              |4040-specific opcodes are handled first; other opcodes are delegated to the 4004 implementation.            |

### CPU configuration

The constructor first invokes `T4004CPU.Create`, then sets the 4040 identity
and processor properties:

|item                    |value                       |
|------------------------|----------------------------|
|Module name             |`4040`                      |
|Description             |`Intel 4040 microprocessor` |
|Architecture            |`arHarvard`                 |
|Address width           |13                          |
|Endianness              |`enLittle`                  |
|Maximum memory address  |`$00FF`                     |
|Maximum code address    |`$1FFF`                     |
|Maximum I/O port address|`$000F`                     |
|Separate I/O bus        |`True`                      |
|Default clock frequency |500000 Hz (500 kHz)         |
|Bus type                |Inherited `btMCS4`          |
|TEST input              |`FTestPin = True`           |

The data-memory and I/O address limits and bus type are inherited from the
4004 implementation or assigned the same values by the base constructor.
The 4040-specific program-counter mask is set to `$1FFF`.

### Reset state

`T4040CPU.Reset` calls the inherited `T4004CPU.Reset`, then sets the ROM bank
to zero, disables interrupts and assigns register pointers for `R0` through
`R7`. The inherited reset clears the execution state, counters, register and
stack records, carry flag, and emits `ceReset`.

|register/state     |value  |
|-------------------|-------|
|`PC`               |`$0000`|
|`A`                |`$00`  |
|`CCR`              |`$00`  |
|`FROMBank`         |`0`    |
|`Running`          |`False`|
|`Halted`           |`False`|
|`InterruptEnabled` |`False`|
|`FFlags.C`         |`False`|
|`TotalCycles`      |`0`    |
|`TotalInstructions`|`0`    |

The constructor configures the internal stack size as seven and allocates
24 entries for `FRegs.R`. The program-counter mask is `$1FFF`.

### Instruction execution

`T4040CPU.Step` performs these operations:

1. Stops immediately when the CPU is disabled (`FEnabled = False`).
2. Calls the inherited `CheckInterrupts` method.
3. Stops if the CPU is halted (`FHalted = True`).
4. Calls the inherited `T4004CPU.Step` to fetch and execute one instruction.

The inherited step reads the opcode from ROM through `FBus.ReadROM`, records
the instruction address and opcode, increments and masks the program counter,
calls the virtual `RunOpCode` method, updates the cycle and instruction
counters, and emits `ceInstructionBoundary`.

The 4040 override does not stop after `CheckInterrupts`; it only checks
whether the CPU is halted before calling the inherited step. If interrupt
checking invokes `DoInterrupt` without halting the CPU, instruction fetching
then continues in the same `Step` call, using the program counter set by the
interrupt handler.

### Interrupt handling

`T4040CPU.DoInterrupt` first calls the inherited interrupt handler. When
`AEvent = ceInterrupt`, it:

1. disables further maskable interrupts by setting `FInterruptEnabled` to
   `False`;
2. stores the current `PC` in the internal stack at `FStack.Pointer`;
3. advances the stack pointer modulo `FStackSize`;
4. selects ROM bank zero by setting `FROMBank` to `0`;
5. sets the program counter to `$003`.

The stack size is configured as seven entries by the constructor. The
interrupt handler does not inspect `AMode` and does not select a different
vector based on that parameter.

### Register and flag structures

The 4040 reuses the inherited `T4004Registers` record. Its fields are:

|field|width / type   |description                                        |
|-----|---------------|---------------------------------------------------|
|`R`  |`array of Byte`|24 four-bit general-purpose registers (`R0`–`R23`).|
|`A`  |`Byte`         |Four-bit accumulator.                              |
|`PC` |`Word`         |13-bit program counter.                            |
|`CCR`|`Byte`         |Three-bit command control register.                |

The inherited `T4004Flags` record contains the following flag:

|flag|type     |description|
|----|---------|-----------|
|`C` |`Boolean`|Carry flag.|

The inherited `T4004Stack` record contains:

|field    |type           |description                                               |
|---------|---------------|----------------------------------------------------------|
|`Pointer`|`Byte`         |Internal stack pointer.                                   |
|`Regs`   |`array of Word`|Stored program-counter values; allocated to seven entries.|

### Register access

`GetRegister` and `SetRegister` convert the supplied register name to
uppercase. The supported names are `R0`–`R23`, `A` and `PC`.

|register  |width |readable|writable|
|----------|------|--------|--------|
|`R0`–`R23`|4 bit |Yes     |Yes     |
|`A`       |4 bit |Yes     |Yes     |
|`PC`      |13 bit|Yes     |Yes     |

`SetRegister` masks `R0`–`R23` and `A` to the low four bits. It masks `PC`
with `FPCMask`, initialized to `$1FFF`.

`GetRegisterCount` returns the number of entries in `PubRegNames4040`.
`GetRegisterName` returns the name for a valid index and `nil` otherwise.
`GetRegisterSize` returns the corresponding size in nibbles and `0` for an
invalid index.

`CCR`, the carry flag and the internal stack are not included in the public
register enumeration.

### Current-instruction information

`GetCurrentInstruction` is inherited from `T4004CPU`. It returns a `TLogRec`
containing the total instruction count, instruction address, raw opcode text,
mnemonic, last instruction cycle count and accumulated cycle count.

The address is formatted as four hexadecimal digits and the opcode as two
hexadecimal digits. Up to two operand bytes are appended when
`FLastInstruction.NumOperand` is greater than zero. Operand bytes are
formatted as two hexadecimal digits.

### State persistence

`T4040CPU` does not override `LoadState` or `SaveState`; it inherits both
methods from `T4004CPU`. The inherited methods read and write the following
data in this order:

|order|data                |
|-----|--------------------|
|1    |`FEnabled`          |
|2    |`FRegs`             |
|3    |`FFlags`            |
|4    |`FStack`            |
|5    |`FLastInstruction`  |
|6    |`FRunning`          |
|7    |`FHalted`           |
|8    |`FTotalCycles`      |
|9    |`FTotalInstructions`|

`LoadState` returns `False` if a stream exception occurs and `True` otherwise.
`SaveState` writes the same fields in the same order and returns `True` after
the write operations complete.
